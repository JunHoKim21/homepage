1. 프로젝트 개요 및 상용화 핵심 전제

1.1 제품 미션 및 15년 차 시니어 설계 가치

본 스타터 킷은 글로벌/국내 스타트업, SI 에이전시 및 엔터프라이즈 B2B SaaS 개발팀이 즉각 프로덕션에 투입할 수 있도록 설계된 풀스택 상용화 베이스 프레임워크입니다.

  • Time to Market 단축: 신규 프로젝트 착수 시 2~3개월이 소요되는 인증/인가(소셜 로그인·2FA 포함), 관리자 CMS, 동적 권한(RBAC), 대용량 미디어 처리, 감사 로그, 엑셀 스트리밍, 주문·결제 상태 머신 등의 기반 작업을 0일로 단축합니다.
  • 실용적 아키텍처와 커스터마이징 편의성 조화: 계층 침범과 안티 패턴은 루트 프로젝트의 통합 ArchUnit 테스트 및 Gradle runtimeOnly 캡슐화로 원천 차단하되, 구매자가 컬럼 하나를 추가할 때 발생하는 불필요한 매퍼(Mapper) 보일러플레이트를 제거한 실용적 도메인 모델(Pragmatic Domain Model)을 채택했습니다.
  • 운영 안정성(Zero-Fault Engineering): 대용량 이미지·엑셀 처리 시의 수학적 JVM 힙 메모리 상한 통제(256MB 이하), JPA Flush 생명주기와 결합된 무결점 감사 로그, Lua Script 원자성 기반의 동시성 토큰 교환 및 탈취 감지, 트랜잭션 커밋 후(AFTER_COMMIT) 캐시 동기화 등 프로덕션 환경의 장애 포인트를 사전 방어 설계로 해결하였습니다.

2. 5대 기술 조건 의사결정 및 라이선스 방어 전략

  1. 경량 멀티 모듈 + 워커 실행 격리: Gradle Multi-Module (starter-core, starter-infra, starter-app-api-public, starter-app-api-admin)로 대고객/관리자 배포 단위를 분리하고, 스케줄러/워커는 starter.worker.enabled=true 프로퍼티를 통해 단일 서버에서만 구동되도록 격리합니다.
  2. Next.js 15 App Router + OpenAPI 계약 자동화: 백엔드 OpenAPI 3.1 스펙에서 TypeScript 타입 및 API 훅을 자동 생성(orval)하여 프론트-백엔드 스펙 불일치를 원천 차단합니다.
  3. PostgreSQL 16 + OpenFeign QueryDSL 6.x + Flyway: Command는 JPA 엔티티 더티 체킹, Query는 QueryDSL DTO 프로젝션을 사용하는 경량 CQRS와 Partial Unique Index 기반의 Soft Delete를 적용합니다.
  4. Stateless JWT + Valkey Lua RTR + Java 21 가상 스레드: 평상시 API 인가는 서명 검증과 로컬 L1 블랙리스트 캐시만으로 무상태 처리하며, 토큰 갱신(RTR)은 단일 Valkey Lua Script로 원자성을 보장하고 관리자 TOTP 2FA를 기본 탑재합니다.
  5. 실용적 Ports & Adapters + Transactional Outbox: 핵심 도메인을 Outbound Port 인터페이스로 보호하고 외부 알림·웹훅은 Outbox 패턴으로 발송을 보장합니다.

3. 최종 시스템 아키텍처 청사진 & 모듈 구조

3.1 실용적 헥사고날(Pragmatic Ports & Adapters) 및 워커 격리

순수 POJO 도메인과 JPA 엔티티를 억지로 분리할 때 발생하는 매퍼(Mapper) 지옥을 막기 위해 starter-core 내부에 JPA 엔티티와 @Transactional까지만 허용하고, QueryDSL 구현체·외부 SDK·배치 워커는 starter-infra로 격리합니다. 

homepage (Root Project - 전체 모듈 통합 ArchUnit 검증 태스크 수행)
 ├── starter-core              (도메인 엔티티, 비즈니스 서비스, 입출력 Port 인터페이스, 공통 예외)
 ├── starter-infra             (QueryDSL 구현체, Valkey/S3/Mail 어댑터, SXSSF 엔진, 조건부 스케줄러, Flyway)
 ├── starter-app-api-public    (대고객 서비스 API — starter.worker.enabled=false 기본 적용)
 ├── starter-app-api-admin     (관리자 백오피스 API — starter.worker.enabled=true 워커 전담 구동)
 └── frontend/                 (Next.js 15 App Router 모노레포 / shadcn/ui 기반)

① runtimeOnly + AutoConfiguration 조립

starter-app-api-*는 starter-core만 implementation으로 참조하고 starter-infra는 runtimeOnly로 캡슐화합니다. 인프라 어댑터는 Spring Boot AutoConfiguration.imports로 등록되어 웹 계층의 직접 참조를 컴파일 타임에 원천 차단합니다.

② 백그라운드 워커 중복 실행 차단

OutboxPollingPublisher, AuditPartitionScheduler, OrphanMediaCleanupJob 등 모든 워커는 @ConditionalOnProperty(prefix="starter.worker", name="enabled", havingValue="true")로 제어하여 Public API 서버에서는 실행되지 않도록 분리합니다.

3.2 루트 통합 ArchUnit 계층 검증 규칙

@AnalyzeClasses(packages = "com.starterkit", importOptions = ImportOption.DoNotIncludeTests.class)
public class ArchitectureLayerRulesTest {

    @ArchTest
    static final ArchRule core_must_not_depend_on_infra_or_apps =
        noClasses().that().resideInAPackage("..core..")
            .should().dependOnClassesThat().resideInAnyPackage("..infra..", "..app..");

    @ArchTest
    static final ArchRule app_must_not_access_infra_directly =
        noClasses().that().resideInAPackage("..app..")
            .should().dependOnClassesThat().resideInAPackage("..infra..");

    @ArchTest
    static final ArchRule entities_must_not_leak_to_controllers =
        noMethods().that().areDeclaredInClassesThat().resideInAPackage("..controller..")
            .should().haveRawReturnType(annotatedWith(Entity.class))
            .orShould().haveRawParameterTypes(anyElementThat(annotatedWith(Entity.class)));
}

4. 5대 킬러 실무 보완 기능 상세 명세

[킬러 1] 수학적 힙 상한(≤ 256MB)이 보장된 대용량 이미지 최적화 파이프라인

OOM & XSS 원천 방어
  • 픽셀 상한선(4096 × 4096) 및 수학적 메모리 통제: 비압축 RGBA BufferedImage 디코딩 시 4096 × 4096 × 4 bytes ≈ 67.1MB가 소요됩니다. 전체 디코딩 전 TwelveMonkeys ImageReader로 헤더만 스캔해 4096px(16.7MP) 초과 시 즉시 거부(Image Bomb 차단)합니다.
  • Source Subsampling & Semaphore(2) 동시성 제한: ImageReadParam.setSourceSubsampling()으로 축소 디코딩을 수행하고 동시 실행 워커를 Semaphore(2)로 제한하여, 피크 타임에도 이미지 처리용 총 힙 메모리가 절대 200~256MB를 넘지 않도록 수학적으로 보장합니다.
  • SVG Stored XSS 차단 & Retina 대응: 악성 스크립트 삽입 위험이 있는 SVG를 배제하고 S3 Range: bytes=0-63 매직 바이트 검증으로 래스터 이미지만 허용합니다. Retina(2x/3x) 디스플레이 선명도를 위해 thumbnail(360px), medium(768px), large(1920px) WebP 및 32글자 BlurHash를 생성하며, 24시간 방치된 PENDING 고아 파일을 매일 정리합니다.

[킬러 2] 트랜잭션 Flush 순서가 보장된 감사 로그(@AuditLog) & 무손실 Fallback

Deadlock & LazyException 제로
  • AOP 우선순위(@Order) 교정으로 Flush 역전 방지: JPA PreUpdateEventListener는 바깥쪽 TransactionInterceptor가 커밋(Flush)할 때 호출됩니다. 따라서 AuditLogAspect에 @Order(Ordered.HIGHEST_PRECEDENCE + 10)을 부여해 트랜잭션 프록시보다 바깥쪽에서 감싸도록 설계합니다.
  • 다중 엔티티 누적(List<EntityAuditSnapshot>) & 메인 스레드 직렬화: 한 트랜잭션 내 여러 엔티티 수정 시 덮어쓰기를 막기 위해 AuditContextHolder가 List<EntityAuditSnapshot>을 누적 관리합니다. PreUpdateEventListener 시점(영속성 컨텍스트 활성 상태)에 @Sensitive 마스킹 JSON으로 즉시 직렬화해 LazyInitializationException을 원천 차단합니다.
  • 실패 Fallback 입력 스냅샷 사전 캡처: 비즈니스 예외 롤백 시 Hibernate PreUpdate가 호출되지 않으므로, AuditLogAspect 진입 시점에 요청 DTO와 SpEL 기반 targetId를 Fallback 입력 스냅샷으로 먼저 캡처해 FAILURE 이력도 빈 껍데기 없이 남깁니다.
  • 커넥션 반납 후 비동기 적재 & JSONL Fallback: 트랜잭션 종료(커넥션 반납 완료) 직후 바깥쪽 AOP의 finally 블록이 비동기 큐로 로그를 전달하며, 큐 포화나 DB 장애 시 로컬 롤링 파일(logs/audit-fallback.jsonl) 및 Valkey Stream에 우회 기록하여 감사 로그 유실을 0%로 방어합니다.

[킬러 3] 무상태 JWT + Valkey Lua 원자적 RTR + Java 21 가상 스레드 인증

Stateless & Lua Atomicity
  • 평상시 완전 무상태(Zero Valkey Hop): Access Token(15분) 검증 시 Valkey 화이트리스트를 조회하지 않고, 서명 검증과 로컬 Caffeine L1 캐시의 blacklist:family:{familyId} 여부만 확인하여 0.01ms 만에 통과시킵니다.
  • Valkey Cluster Hash Tag({familyId}) & EXPIRE 메모리 누수 방지: Valkey Cluster CROSSSLOT 에러 방지를 위해 모든 RTR 키에 {familyId} Hash Tag를 적용합니다(lock:{F1}:rt:RT_1, token:{F1}:rt:RT_1, token:{F1}:rt:RT_2, token:{F1}:grace:RT_1, family:{F1}). 또한 family:{F1} Set에도 Refresh Token과 동일한 EXPIRE(1,209,600초)를 설정해 영구 메모리 누수를 방지합니다.
  • 단일 Lua Script 원자적 RTR & 10초 Grace Window: 기존 토큰 USED 전환, 신규 토큰 ACTIVE 저장, 패밀리 Set 등록·만료, 10초 유예 캐시 생성 및 락 해제를 rotate_refresh_token.lua로 원자화합니다. 동시 요청(Req B)은 Java 21 가상 스레드에서 락 해제 대기(최대 500ms) 후 동일하게 EVAL rotate_refresh_token.lua를 호출해 Lua 내부에서 Grace Window를 확인·반환합니다.
  • 탈취 재사용 감지(Reuse Detection): 10초 유예 기간 이후 USED 상태 토큰이 인입되면 즉시 family:{F1} 전체를 삭제하고 Pub/Sub으로 L1 블랙리스트를 전파해 전 기기를 강제 로그아웃시킵니다.

[킬러 4] SXSSF + DTO 프로젝션 & 자동 시트 분할 엑셀

영속성 컨텍스트 1차 캐시를 우회하는 QueryDSL DTO 프로젝션과 Keyset(id > :lastSeenId) 커서를 결합하고, 단일 시트 100만 행 도달 시 자동으로 Sheet_2를 분할 생성합니다. 진행률은 Valkey에 실시간 갱신·DB 업데이트는 1만 건 단위로 스로틀링하며, 완료된 export_jobs 파일은 Next.js BFF 메모리 버퍼링/타임아웃을 피하기 위해 S3/SeaweedFS Presigned GET URL을 발급해 브라우저가 직접 다운로드합니다.

[킬러 5] AFTER_COMMIT 기반 동적 설정 & RBAC 캐시 전파

Caffeine(L1) + Valkey(L2) 2단계 캐시를 적용하며, @TransactionalEventListener(phase = AFTER_COMMIT)를 통해 DB 커밋이 완전히 확정된 직후에만 Valkey 갱신 및 Pub/Sub 무효화 메시지를 발행하여 Stale Cache Read를 원천 차단합니다.

5. 핵심 도메인 데이터 모델링 및 ERD 명세 (PostgreSQL 16 표준)

모든 테이블의 내부 PK는 BIGINT GENERATED ALWAYS AS IDENTITY로 통일하고 외부 노출 식별자는 UUIDv7(public_id)을 사용합니다. 논리 삭제(deleted_at) 시 재가입·슬러그 재사용 충돌을 막기 위해 PostgreSQL Partial Unique Index(WHERE deleted_at IS NULL)를 전면 적용했습니다. 

-- 1. 대고객 회원 및 OAuth2 소셜 계정 (Partial Unique Index 적용)
CREATE TABLE members (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    public_id UUID NOT NULL UNIQUE,               -- 외부 API 노출용 UUIDv7
    email VARCHAR(255) NOT NULL,
    password_hash VARCHAR(255),                   -- 소셜 전용 가입 시 NULL 허용
    nickname VARCHAR(100) NOT NULL,
    phone_number VARCHAR(50),
    status VARCHAR(30) NOT NULL DEFAULT 'ACTIVE', -- ACTIVE, SUSPENDED, WITHDRAWN
    role VARCHAR(30) NOT NULL DEFAULT 'USER',     -- USER, VIP
    site_code VARCHAR(50) NOT NULL DEFAULT 'MAIN',
    email_verified_at TIMESTAMP WITH TIME ZONE,

환경 변수 보간(${VAR:-default}), 전 컨테이너 Healthcheck, 그리고 SeaweedFS 초기 S3 버킷(starter-bucket) 자동 생성 초기화 컨테이너(seaweedfs-init)를 포함하여 docker compose up -d 즉시 에러 없이 구동됩니다. 

services:
  postgres:
    image: postgres:16.4-alpine
    container_name: starter-postgres
    restart: unless-stopped
    environment:
      POSTGRES_DB: ${POSTGRES_DB:-starter_db}
      POSTGRES_USER: ${POSTGRES_USER:-starter_user}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-starter_secure_password_2026}
    ports:
      - "${POSTGRES_PORT:-5432}:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]
      interval: 5s
      timeout: 5s
      retries: 5

  valkey:
    image: valkey/valkey:8.0.1-alpine
    container_name: starter-valkey
    restart: unless-stopped
    command: ["valkey-server", "--requirepass", "${VALKEY_PASSWORD:-valkey_secure_pass_2026}", "--appendonly", "yes"]
    ports:
      - "${VALKEY_PORT:-6379}:6379"
    volumes:
      - valkeydata:/data
    healthcheck:
      test: ["CMD", "valkey-cli", "-a", "${VALKEY_PASSWORD:-valkey_secure_pass_2026}", "ping"]
      interval: 5s
      timeout: 3s
      retries: 5

  seaweedfs:
    image: chrislusf/seaweedfs:3.79
    container_name: starter-seaweedfs
    restart: unless-stopped
    command: "server -dir=/data -s3 -s3.port=8333 -filer"
    ports:
      - "${S3_PORT:-8333}:8333"
      - "9333:9333"
      - "8888:8888"
    volumes:
      - seaweeddata:/data
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://localhost:9333/cluster/status >/dev/null 2>&1 || exit 1"]
      interval: 5s
      timeout: 5s
      retries: 5

  seaweedfs-init:
    image: curlimages/curl:8.10.1
    container_name: starter-seaweedfs-init
    depends_on:
      seaweedfs:
        condition: service_healthy
    entrypoint:
      - /bin/sh
      - -c
      - |
        set -eu
        echo "Initializing default S3 bucket (starter-bucket) in SeaweedFS Filer..."
        for i in 1 2 3 4 5; do
          if curl -sf -X POST "http://seaweedfs:8888/buckets/starter-bucket/" >/dev/null; then
            echo "Default S3 bucket initialized successfully."
            exit 0
          fi
          HTTP_CODE=$$(curl -s -o /dev/null -w "%{http_code}" "http://seaweedfs:8888/buckets/starter-bucket/")
          if [ "$$HTTP_CODE" = "200" ] || [ "$$HTTP_CODE" = "409" ]; then
            echo "Default S3 bucket already exists (HTTP $$HTTP_CODE)."
            exit 0
          fi
          echo "Attempt $$i/5 failed (HTTP $$HTTP_CODE), retrying in 2s..."
          sleep 2
        done
        echo "ERROR: Failed to initialize SeaweedFS bucket after 5 attempts." >&2
        exit 1
    restart: "no"

  mailpit:
    image: axllent/mailpit:v1.21
    container_name: starter-mailpit
    restart: unless-stopped
    ports:
      - "${MAILPIT_UI_PORT:-8025}:8025"
      - "${MAILPIT_SMTP_PORT:-1025}:1025"
    healthcheck:
      test: ["CMD", "/mailpit", "readyz"]
      interval: 5s
      timeout: 3s
      retries: 5

volumes:

  valkeydata:
  seaweeddata:
